# Danmu Fusion 1.5.2

本次修复聚合来源不容易找到、播放器来源名称不明确的问题，保留 1.5.1 的来源记忆、错误诊断、备用来源和大轨道性能改进。

## 聚合入口与显示

- 服务端原生聚合资源明确显示「【聚合】」，保留实际平台组合；已经验证通过的跨 API 分集聚合同样标为「聚合」。
- 复用近期有效、身份和接口指纹一致的原生聚合候选，减少多 API 搜索中较快的单平台结果遮住晚到聚合入口的情况。新服务器响应优先，不覆盖已返回的空结果。
- 来源平台随电视剧、电影和集数动态变化，没有固定只获取腾讯、爱奇艺、爱一帆或任意三个平台。实际参与平台仍由服务器配置及该资源是否可用决定。
- 单平台资源和仅提供统一选集的「跨 API 选源」入口保留独立标识，不将未验证资源冒充为聚合。

## 实际验证

使用 API1 自建服务器，在 macOS Rex 1.0.2 中重新搜索、选择聚合来源并播放《爱情公寓4》第7集，同时读取 AWS 容器日志。日志记录多个平台实际抓取及聚合完成，轨道返回 59,949 条弹幕，包含不同平台的来源标签；新版「【聚合】」入口和实际弹幕显示均已确认。另用正式 Widget 入口验证两部电影的原生聚合整轨与进度窗口：《哪吒之魔童降世》177,330 条、《长安三万里》261,217 条。样本的平台组合不代表其他作品的平台范围。

完整自动回归 244/244，另两份身份脚本通过；原生适配 29/29、多 API 34/34、新增聚合显示与隔离回归 8/8 均包含在完整数量中。安装依赖、构建和产物一致性检查通过。测试使用的私人地址、Token、认证信息和原始日志不进入仓库或发行附件。

## 性能与兼容

本次保留 1.5.1 的轨道准备复用、并发请求合并和分钟索引，不改变弹幕内容、时间、颜色或位置。固定 Mock 数据、独立 Node/Widget VM、三次中位数重新对比 1.5.0：22 万条轨道首载 2261.09 → 1276.28 ms；4000 条轨道 80 次进度跳转 2128.04 → 246.69 ms；12 个并发进度窗口 838.45 → 125.83 ms。必要请求数不变，多余重复请求为 0。80 次跳转场景观察堆占用 24.04 → 11.56 MiB；部分大轨道和连续切集的内存采样仍有上升，详见测试报告。这些为模拟环境结果，不是 iPhone 性能数据。

保留模块 ID、API1 原配置键、1～3 API 配置、原生 withRelated、多 API 真实 ID 路由及安全聚合边界，不增加设置，不修改服务器的平台配置。继续采用 AGPL-3.0-only，保留原作者和上游版权信息。

## 升级与已知限制

在播放器中更新同 ID 的 Danmu Fusion 模块。原有三个 API 地址继续使用；升级后重新搜索弹幕并选择带「【聚合】」的资源。Rex 可能保留旧列表，必要时重新进入播放会话。Release 提供独立 JS、两个安装索引、源码 ZIP、LICENSE 与 SHA256SUMS。

首次冷搜索、缺少有效候选记录或宿主提前结束慢接口回调时，仍不保证首次列表包含所有 API。候选复用沿用既有有界存储和 5 分钟有效期，不缓存整轨；接口或凭据变化后重新搜索。单集标识依据服务端明确的多平台分集标记，实际成功平台以服务器日志和返回轨道为准。

本次实际播放器验证范围为 macOS Rex。原版 Forward、iOS/iPhone/iPad 真实设备、其他所有平台的线上可用性及真实跨 API 时间轴合并：未验证。服务端聚合与跨 API 聚合仍分别遵守原有校验，不因显示修复放宽规则。
