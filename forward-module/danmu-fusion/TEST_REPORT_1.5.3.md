# Danmu Fusion 1.5.3 聚合流程、清理与验收

日期：2026-10-26。基线：1.5.2及其README更新（7b64353ef04739368cbae93d2060ff760121ce00）。

## 本次行为

公开搜索/选集只返回聚合项，平台组合在标题前部以“平台A&平台B&…”显示。当前集单独核对资源及实际返回的来源标签；上一集平台减少或原主平台缺集时，不把它作为本集其他平台聚合的前提。仅剩一个有效平台时明确标注，不伪称多平台结果。历史保存的真实ID和来源绑定路由仍可加载。

源代码中的显示名称映射仅用于中文名称，不是抓取白名单。未知平台代码可以直接展示。服务器从当前配置与真实候选发现平台；按严格作品身份、原始集号构建资源并集，不使用数组下标或上一集平台名单。自定义合并规则非空时保留原受保护路径，本次不宣称已改写该路径的行为。

已知当前季集/电影时，搜索前先核对当前轨道的平台标签；明确失败或无弹幕不宣传可用聚合。平台摘要最多32条、3分钟、48000字符，仅保存摘要，不保存评论。公开整轨与进度调用统一来源/真实ID上下文，以复用可缓存轨道。新建跨API聚合等待各成员完成或由宿主报错，仍要求同作品、同集、同片长、同视频身份和版本/语言无冲突。

交互/并行负载期间，既有10万条压力测试出现超过5000ms门槛的波动。服务端测试改为按文件串行执行，以隔离不同测试进程的CPU竞争；保留5000ms断言及全部用例，最终以完整命令重新验证。

API1服务器已获用户明确授权：备份两份现用严格保护层文件，更新后重启现有容器，语法及运行状态检查通过，保留可恢复备份。未修改API地址、Token、来源启用配置、凭据或偏移配置。正式1.21.7原文件通过受检查生成脚本生成覆盖文件，未在已打补丁文件上叠加。
