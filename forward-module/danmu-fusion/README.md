# Danmu Fusion · 弹幕融合 1.5.3

支持同时配置 **1～3 个弹弹 Play 兼容 API** 的 Forward/Rex 弹幕模块。保留 1.4.5 已验证的搜索筛选、年份辅助匹配、标准选集、原生 withRelated 聚合、样式及进度分片流程。

## 安装与升级

1. 导入 [danmu-fusion.js](./danmu-fusion.js)，或使用 [widget.fwd](./widget.fwd) 安装索引。
2. 「弹幕 API 1（主要接口）」沿用 `danmu_api_url`，原地址自动保留。
3. 需要时再填写「弹幕 API 2（可选）」和「弹幕 API 3（可选）」，不需要全部填写。
4. 从旧版升级时更新同 ID 模块，原有三 API 配置保留。升级后重新搜索弹幕，选择带「【聚合】」的资源及对应集数；若播放器仍保留旧列表，可重新进入播放会话。首次冷搜索仍可能缺少晚到 API，详情见下文。

模块 ID 仍是 `tzb360.danmu.fusion`。界面只有三个地址输入框，没有模式、来源规则、超时或去重等技术设置。Node 部署的安装入口仍为 `https://你的服务器/widgets/danmu-fusion/widget.fwd`。

```text
https://example.com/your-token
https://example.com/proxy/your-token/api/v2/
https://example.com/proxy/api/v2?token=your%2Fencoded%2Btoken
```

每框填写一个地址。空项忽略，错误项单独诊断，不阻断其余地址。规范化末尾 `/api/v2`、旧 `/api/forward/danmaku`、主机大小写及默认端口后，重复地址只请求一次。Token、代理路径大小写、百分号编码和认证查询内容原样保留；旧 Forward 地址仅去掉已知媒体查询参数。不要用换行把多个地址塞进同一框。

## 搜索与选择

当前公开入口只展示聚合选项，平台组合在标题前部以「平台A&平台B&…」显示。每一集从自己的资源信息与实际返回评论重新核对平台；不继承上一集的平台名单，不要求某个主平台必须存在。只有一个可用平台时明确注明「本集仅1个平台」，不另列独立平台选项。

每个 API 保留稳定的片名、影视类型、年份、季数和衍生内容筛选。多 API 搜索优先等待原生聚合候选，单平台快结果不抢占；没有原生聚合时，仅展示详情证明同集同版本的跨 API 聚合。新跨 API 聚合等待成员请求完成或宿主原生失败后再返回，不把首次部分响应当成完整结果。全部原生请求悬挂时，仍依赖宿主超时能力。

已知当前季集或电影时，搜索会先加载当前轨道并核对来源标签，再展示实际平台组合；无当前集上下文时，作品项注明「按集显示平台」，分集列表各自显示平台。明确 HTTP 失败或当前集无弹幕时不宣传可用聚合；服务器异步准备时保留准备中状态。未提供评论来源标签的兼容接口只能使用其明确的分集资源信息，不能伪造实际平台统计。

平台摘要使用 Widget.storage，最多32条、3分钟、48000字符，只保存摘要及来源指纹派生键，不存完整评论或凭据。地址变化、剧集 ID 不同或过期均重新核对。公开整轨与进度入口统一使用来源绑定的真实 ID，使预核对与播放可以复用合格缓存；超大轨道仍不缓存，因此可能再次下载。

## 安全聚合

服务器原生聚合沿用 withRelated=true。自建服务端严格保护层按确切片名、类型、年份、季数和版本建立候选，然后按原始标题证明的集号构建资源并集。主平台缺集、来源顺序改变或其他平台新增集数不影响当前集其余来源的组合；不使用数组下标、模糊集名、跨季切片或上一集信息。电影正片单独验证，分段、预告、语言/版本冲突不自动合并。

跨 API 仍要求：同作品身份、年份、类型、季数；同一明确集号或电影正片；相同明确片长；相同内容 Hash 或官方视频资源身份；剪辑版、语言及 TMDB 身份无冲突。缺少证据时不自动混合，也不在新的选择界面提供单平台选源列表。旧版保存的真实 ID 与已绑定路由仍可加载，升级后应重新搜索。

## 来源绑定与历史选择

仅配置 API 1 时继续使用真实 animeId 和 commentId，保留 1.4.5 使用体验。多 API 使用带来源指纹的轻量选择 ID，内部发送的仍是各自真实协议 ID；相同 ID 不会跨 API 串线。

来源指纹是规范化完整地址的 SHA-256，ID、诊断与新缓存键不包含 API 地址或完整 Token。选择 ID 自带路由信息，换一个 Widget 运行时、存储不可用或只传 commentId，也能路由到正确 API；来源顺序变化不改变指纹。

修改/删除来源地址或 Token 后，其旧选择会明确要求重新搜索，不按新槽位猜测路由。1.4.5 的无来源裸 ID 在多 API 模式下也要求重新选择；仅 API 1 模式允许原选择，并用轻量历史指纹检测已经观察到的地址变化。首次升级且没有历史记录时，无法证明裸 ID 原来属于哪台服务器，按原 API 1 契约兼容。清空宿主存储也会丢失这种裸 ID 历史保护。

## 来源推荐记忆与备用切换

选择某部电视剧的聚合 API 并成功加载后，同作品后续集数会优先推荐该 API 的聚合资源。电影同样支持。只记推荐顺序，不复用上一集的 commentId，也不放宽匹配或安全聚合条件。作品名、类型、年份、季数、可用 TMDB 身份、播放版本及语言均参与隔离；缺少年份/类型/季数等可靠信息时不建立记忆。

使用宿主的 `Widget.storage` 保存最多 48 条来源偏好，30 天后过期，只持久化作品摘要和来源指纹；不记录地址、Token 或弹幕。接口地址或凭据集合变化会使推荐记忆失效；仅重排 API 槽位可继续按指纹识别。存储不可用时本次运行仍可使用内存；宿主清理存储或每次重建且不持久化时无法保证跨会话记忆。慢 API 尚未返回时，不会为等待推荐来源延迟已有结果，重新搜索后可补充。

聚合 API 取得真实详情时，可以附带最多两个已完成验证的备用。只有同作品、同季集、同片长、同内容 Hash/官方视频资源且剪辑版/语言一致，才允许当前来源失败后依次尝试；重复集号不猜选。备用详情晚到时，不承诺本轮选择已附带备用。旧 1.5.0 选择 ID 继续能加载，但要重新搜索选集才能携带新增证据。

切换只返回一条备用来源的完整结果，不拼接、不改 cid、文字、时间、颜色或位置；原始故障保留在日志及安全诊断中，每个备用最多尝试一次。有效但无弹幕的进度窗口不触发切换。某个原生请求一直悬挂时，仍需宿主超时后才能判断失败，脚本不能自行中止它。

## 错误提示与反馈

通过宿主已支持的模块日志输出简体中文阶段提示，覆盖地址格式、401/403 认证、404 地址、5xx 服务端、网络、原生超时、返回格式、无搜索结果、当前集无弹幕、绑定失效及不符合安全聚合条件。没有调用额外通知/Toast 接口。失败返回及备用切换结果携带安全 `message` / `diagnostics`，播放器是否额外展示这些字段取决于宿主，不能承诺原生弹窗。

模块诊断最多保留 64 条事件，返回摘要最多 12 条；只含模块版本、固定阶段/分类/中文提示、HTTP 状态及数量。原始宿主异常、服务端错误文本和认证元数据不进入生成的诊断。反馈时可复制 `[Danmu Fusion]` 开头的诊断行，并附播放器/系统版本、作品类型和季集。不要发送原始网络请求、设置截图、地址、Token 或认证头。

## 去重、容量和等待

单 API 完全沿用 cid、完整 p、m 相同才去重的原则。跨 API 仅在已经证明能安全聚合之后，再用明确的上游来源和原始记录 ID，连同完整 p、m 做精确重放去重；没有可信来源标识的相同数字 cid、相同短句仍保留。不做模糊文本去重，不改时间、颜色、位置或文字。

聚合记录的 cid 按 API 指纹隔离，旧选择及新聚合流程的后续进度响应保持一致。合并后只按原时间排序，不做时间轴校准。片长/视频版本显式变化时取消该成员自动合并。

缓存仍为最多 4 条、合计约 2 MiB、3 分钟；可缓存轨道只校验一次并建立分钟索引，输出副本避免播放器修改污染缓存；估算加入对象与索引开销，因此部分原先临界大小的轨道会更早跳过缓存。大轨道、错误、空数据和下载任务不缓存。整轨上限仍为 50 万条、6400 万字符 JSON；跨 API 合并超过边界时返回一条完整健康来源，并提供容量降级诊断，不截断伪装完整。

每个 API 最多两个并行冷查询，以兼容 Rex 的剧名搜索和保存关键词重试；公开 HTTP 边界最多 12 个不同在途请求，相同请求合并，不建立无限排队或轮询。没有 setTimeout、fetch、URL、AbortController 或 Node 运行依赖。单个慢 API 不拖住已有有效结果；**所有原生请求都不结束时，硬性中断仍取决于宿主的原生超时/取消能力**，模块不会伪造一个宿主不支持的超时参数。单 API 冷搜索本身的 35～66 秒延迟也无法由客户端消除。

标准整集首次返回完整轨道；进度入口筛选 60 秒窗口。仅服务端实际提供 barrage_list 时使用原有 GET 分片，保留标准降级。日志只输出固定阶段、错误码和数量，不记录请求地址、认证头、响应正文或原始异常。

## 开发和验收

```sh
npm run build:forward-fusion
node scripts/build-danmu-fusion.mjs --check
npm run test:all
npm run test:forward-native
npm run test:forward-multi
npm run benchmark:forward
```

真实远程验证使用已有测试地址：

```sh
DANMU_API_URL=… npm run test:forward-live
DANMU_API_URL=… DANMU_API_URL_2=… DANMU_API_URL_3=… npm run test:forward-multi-live
```

`adapter.js` 保留稳定协议流程；`multi-api.js` 只增加外层来源管理和保守聚合；`transport.js` 中的旧客户端引擎继续保留，不接入公开播放入口。构建产物无运行时依赖。
