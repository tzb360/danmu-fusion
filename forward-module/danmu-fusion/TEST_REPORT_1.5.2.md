# Danmu Fusion 1.5.2 聚合入口修复与验证

日期：2026-10-26。基线：已公开 1.5.1（566dc1301138e175accb69f73afb462245b3c772）。

## 问题与结论

用户提供的 iOS 截图显示 API2 的独立平台来源，没有可见的原生聚合项。截图不能证明服务器已停止聚合。实际复现发现多 API 首个有效结果返回、晚到候选仅留在运行时缓存、播放器额外保留来源列表，共同造成原生聚合项难以找到。重启会话、隔离 API1 后，旧版也能找到服务器原生聚合；因此本次修复入口可见性和显示，不用单源改名冒充聚合。

原生聚合的抓取发生在服务器。客户端继续请求服务器真实 episodeId，并保留 withRelated=true；不在客户端硬编码平台列表或再次抓取、偏移同组弹幕。

## 实现边界

- 聚合候选和具有明确多平台分集标记的条目显示「【聚合】」，公开 source 为「聚合」，原 source 留在 originalSource。返回的原平台组合不被重写。
- 单个平台、同平台别名重复、尚未验证的跨 API 选源不误标；跨 API 分集仍需同作品、同季集、同片长和同视频指纹证据。
- 多 API 搜索读取既有有界轻量查找记录，最多读取索引末尾 32 条、每条上限 200000 字符，仅补入未过期的原生聚合候选。来源指纹、作品、类型、年份、季数、身份和明确版本/语言必须匹配；最多补入 32 个候选。
- 只补入首次返回批次中尚未完成的 API。已完成新响应（包括空结果）优先；不新增服务、平台白名单、队列、定时器或评论持久化。
- 不修改服务器环境变量、容器、启用平台、严格保护层或原始评论。

## macOS Rex 与 AWS 联合实测

环境：Rex 1.0.2（11），macOS；API1 指向用户自建 AWS 弹幕服务器，容器使用 logvar/danmu-api:1.21.7。仅只读检查服务器日志，未改变生产配置。私人地址、认证信息、原始日志和截图均留在本地忽略目录，不随版本发布。

1. 隔离 API1，清除本轮会话影响后重新搜索《爱情公寓4》（2014，第4季）。旧版可找到 from tencent&iqiyi&aiyifan 的原生聚合候选，证明服务端功能仍存在。
2. 在 Rex 选择该候选，从第3集切换第7集，实际显示弹幕。UTC 05:51:25～05:51:33 的服务器日志依次记录 aiyifan、tencent 和 iqiyi 的真实抓取，随后出现「聚合原始数据完成」。后续请求中也观察到服务端缓存命中，不将缓存命中冒充每次重新抓取。
3. 安装正式生成的 1.5.2 文件，模块设置确认版本 1.5.2。重新搜索后来源列表显示并勾选「【聚合】爱情公寓4(2014)…from tencent&iqiyi&iqiyi&aiyifan」。选择、播放第7集后实际显示大量弹幕；UTC 06:05:16～06:05:23 的日志再次记录该集多平台抓取及聚合完成。
4. 恢复原有 API2/API3，逐项校验三地址与备份完全相同；新会话中同时看到「【聚合】」项与 API2 的 360/tencent/iqiyi 等独立来源。播放器会保留部分旧名称，所以升级说明要求重新搜索/进入会话。测试结束停止播放。

服务器上同一平台可能有多个匹配资源，候选中 iqiyi 因而可能重复。这是原生返回，不代表新增了平台，也不在显示层擅自去掉源。日志原始聚合条数含重复平台分支、后续服务端精确合并，不能等同于最终返回条数。

## 可重复性能基准

执行 node --expose-gc forward-module/danmu-fusion/benchmark-1.5.1.mjs。脚本名称保留历史兼容，当前版本从正式构建元数据读取。固定 1.5.0 构建、固定 JSON HTTP、每样本独立 Node 进程及 Widget VM，三次中位数。环境和逐次原始数字见 benchmarks/1.5.2-vs-1.5.0.json。这些不是 iOS 真机数据；内存是回调后观察值，不是严格分配峰值。

| 场景 | 1.5.0 ms | 1.5.2 ms | 必要请求数（两版一致） | 多余重复请求 |

| 220001 条首次加载 | 2261.09 | 1276.28 | 4（含后续3次跳转） | 0 |
| 同轨道3次跳转 | 8371.71 | 4903.72 | 同上 | 0 |
| 4000 条轨道80次跳转 | 2128.04 | 246.69 | 1 | 0 |
| 12个并发进度窗口 | 838.45 | 125.83 | 2（含首载） | 0 |
| 连续6次切集 | 237.51 | 204.28 | 7（含首载） | 0 |

| 场景 | 观察堆 MiB：1.5.0 → 1.5.2 | GC后保留堆增量 MiB | 观察 RSS MiB |
|---|---|---|---|

部分临时堆和 RSS 有增加，不能宣传全场景内存下降。测量期间执行了播放器等本机工作，绝对耗时仅适用于本轮环境，不能与历史测量混算。整轨50万条/6400万字符、有界缓存4条/约2MiB/3分钟、超大轨道不缓存且不截断的边界仍由回归覆盖。

## 已知限制与未验证范围

- 首次冷搜索、无有效元数据、过期或宿主提前结束晚到回调时，首批列表仍可能缺少慢 API。没有伪造宿主超时、强制刷新或后台更新接口。
- 原版 Forward：未验证；iOS/iPhone/iPad：未验证；用户截图仅用于定位问题，不能算本次真机测试。
- macOS Rex：上述搜索、原生聚合选择、切集、新构建安装及弹幕显示已验证；长时间连续播放和手机内存未验证。
- 真实跨 API 时间轴合并和备用切换：本次未验证；确定性正反例回归通过，不以原生聚合实测替代跨 API 验收。
- 其他平台/作品线上可用性依赖服务器和上游，不因平台名可识别就声称抓取成功。
