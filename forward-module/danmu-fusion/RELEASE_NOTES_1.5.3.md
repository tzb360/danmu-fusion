# Danmu Fusion 1.5.3

这次更新围绕“按当前集动态聚合”调整完整流程，选择界面只提供聚合选项，优先显示「平台A&平台B&平台C…」的实际组合。

## 聚合体验

- 不再列出各平台的独立选源项。每集重新核对可用资源及实际返回的来源标签，电影同样支持，没有固定只获取某三个平台。
- 上一集某平台有弹幕、下一集缺失时，继续聚合其余已确认来源；原主平台缺集也不会挡住其他平台。只剩一个平台时明确注明「本集仅1个平台」，不伪称多平台结果。
- 自建服务端严格保护层按原始标题的明确集号构建资源并集，不使用数组位置或上一集的平台名单。电影保留正片、版本与语言边界，补充「第1集 正片」和单一纯分辨率正片标签的兼容。
- 聚合平台组合放在标题前部，减少播放器截断长片名后看不到平台的情况。未通过同集同版本验证的资源不会强行跨 API 混合。

## 修复与清理

统一公开整轨、进度及平台预核对的请求上下文，使合格缓存可复用；保留50万条/6400万字符容量边界、有界缓存及超大轨道不缓存策略。平台摘要独立限制为32条、3分钟、48000字符，不保存整轨或凭据。

删除两个在本仓库条件恒为假的旧工作流，修复 EdgeOne 路由文件名、请求体和请求头处理，移除该适配器的完整认证请求日志。有效部署入口、历史基准、测试证据、许可证和上游版权信息保留。

## 验证与升级

完整自动回归268项、两份身份脚本、原生29项和多API34项检查通过；其中原生与多API检查已计入完整数量。新增16项公开聚合入口、6项按集资源并集和2项EdgeOne回归。macOS Rex实际确认只显示聚合项；API1的AWS严格保护层已按用户授权备份、更新并检查服务恢复，真实电视剧和电影聚合及进度窗口通过。完整数据、性能成本与文件清理依据分别见 TEST_REPORT_1.5.3.md 和仓库根目录 REPOSITORY_AUDIT_1.5.3.md。

更新同 ID 模块即可保留原 API1～3配置，随后重新搜索弹幕。Rex若保留旧列表，可使用其实际支持的请求缓存刷新入口，再重新进入播放。自建其他服务器的用户需按 SERVER_NATIVE_MERGE.md 更新严格保护层，单独更新客户端不会改写外部服务器。

已知当前集时的来源核对会增加首次搜索等待。小轨道可复用缓存；超大轨道预核对后播放可能再次下载，不能把该成本描述为零重复请求。跨API聚合等待实际请求完成或宿主原生报错，不伪造客户端超时。原版Forward、iOS/iPhone/iPad真机、全部作品和全部上游缺集组合未验证；跨API实机故障切换仍未逐项验收。
