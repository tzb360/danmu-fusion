# Danmu Fusion 1.5.1 测试与性能报告

日期：2026-10-26（Asia/Shanghai）。开发基线为最新远程主分支 `09bd904`；其相对正式 `v1.5.0` / `d7815cc` 仅增加文档，不改变稳定协议。原工作区已有改动保留，开发在独立工作副本完成。

## 交付功能

- 来源记忆：成功加载独立来源后，按作品身份/类型/年份/季数/版本/语言推荐；电影及连续剧集覆盖。只持久化摘要与来源指纹，48 条、30 天过期、8 个可选存储操作边界；接口凭据集合变化即失效。推荐不传递上一集 ID，也不允许突破匹配/合并规则。
- 错误诊断：使用宿主 `console.log`，失败/切换返回安全中文提示及最多 12 条事件摘要；区分地址、401/403、404、5xx、网络、原生超时、格式、无结果、无弹幕、来源失效和安全证据不足。不依赖不存在的 Toast；宿主是否展示额外响应字段未作保证。
- 备用切换：独立来源仅携带已通过实际详情证明同作品、同集、同片长、同 Hash/官方视频资源、同剪辑/语言的备用；最多两个，各试一次，保留原错误；不合并、不改原记录、有效空窗口不切换。证据不足或晚到时保留独立选源。
- 性能：同键请求共用轨道准备，缓存内只校验一次并用分钟索引取窗，输出副本保护缓存；超大轨道提前停止缓存大小估算；首批多 API 响应不再被未完成的同批请求状态持有。
- 安全边界保留：50 万条/6400 万字符整轨限制，4 条/约 2 MiB/3 分钟缓存，最大 12 个原生在途请求与 12 个轨道准备任务，无新服务、计时器、轮询或无界队列。对象及索引也计入缓存估算，部分临界轨道会比旧版更早跳过缓存。

## 1.5.0 性能对照

运行环境：Apple M2、macOS arm64、Node v24.19.0；每个版本/场景均运行 3 个独立 Node 进程，取中位数，固定 JSON Mock HTTP。基线直接使用正式 1.5.0 构建，SHA-256 为 `1f8310aa7e84d0c6e1be3858b9656ab5eca9f68cb3e34284ecd62a702877ed24`。新构建摘要、全部单次样本、RSS 采样均见 [原始可重复结果](./benchmarks/1.5.1-node.json)。

复现：

```sh
npm ci
npm run build:forward-fusion
npm run benchmark:forward
# 可用 DANMU_BENCH_SAMPLES / DANMU_BENCH_REPORT 改变样本数或保存报告
node forward-module/danmu-fusion/benchmark-multi.mjs
```

下表均为 **1.5.0 → 1.5.1**；耗时单位 ms，内存单位 MiB。后续阶段不含首次加载；请求数含初次请求。大轨道不缓存，因此三个独立跳转仍需再次请求，不能把这四次必要请求称为重复。

| 场景 | 首次加载 | 后续阶段合计 | HTTP 次数 | 多余重复请求 | 观察到的最高堆占用 | GC 后保留堆增量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4000 条、80 次窗口跳转 | 15.71 → 14.61 | 644.4 → 81.03 | 1 → 1 | 0 → 0 | 23.74 → 11.58 | 0.83 → 0.99 |
| 220001 条、3 次跳转（跳过缓存） | 825.17 → 529.36 | 2794.52 → 1506.3 | 4 → 4 | 0 → 0 | 274.13 → 278.57 | 0.56 → 0.56 |
| 4000 条、12 个并发新集窗口 | 15.57 → 15.45 | 187.62 → 25.85 | 2 → 2 | 0 → 0 | 25.59 → 10.54 | 4.04 → 2.84 |
| 4000 条、连续加载 6 个新集 | 16.23 → 14.7 | 80.8 → 74.28 | 7 → 7 | 0 → 0 | 13.06 → 17.27 | 2.26 → 1.66 |

内存是在每次回调后采样，包含 VM、测试夹具、解析与结果对象；不是逐分配峰值，也不是严格的播放器独占内存。12 个并发窗口样本保留返回结果用于校验，其保留堆包括这些结果。不是所有资源指标都降低：大轨道采样堆占用和连续切集的临时堆占用有上升，可缓存窗口略增保留堆以换取索引；没有把 GC 波动描述成稳定内存下降。大轨道仍不常驻缓存。**全部是 Node/Widget VM 模拟环境，不是真实 iPhone、公网延迟或手机内存承诺。**

## 兼容与已知限制

保持 1～3 API、danmu_api_url、模块 ID tzb360.danmu.fusion、1.4.5 以来的搜索/年份复核/选集/评论、原生 withRelated、多 API 指纹与真实 ID 隔离、拒绝无依据合并及 Forward/Rex 现有接口约定。1.5.0 历史来源 ID 可正常加载，需重新搜索选集才能获得新增记忆/备用证据；仅 API 1 的旧裸 ID 行为保持不变。

来源记忆在成功的独立轨道或非空进度窗口加载后建立，不把探索详情或空进度窗口当作用户确认，不为聚合选择猜一个首选 API。接口无可靠年份/类型等证据时继续独立使用。慢接口尚未返回时首次列表可能没有该来源，宿主列表缓存可能还需重新搜索或新播放会话。

标准 API 没有明确视频版本证据时无法自动备用或跨 API 合并。单个源悬挂时不能抢先判断失败；全部原生请求都悬挂时等待上限由宿主控制。模块未伪造 timeout/AbortController；未实现 1.6 跨 API 聚合增强或双渠道。许可保持 AGPL-3.0-only，原作者和上游署名保留。
